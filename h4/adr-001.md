# ADR-001: Fusión de Strategy y Observer

## Título

ADR-001 - Fusión de Strategy y Observer para la gestión de derivaciones del Sistema de Gestión de Correspondencia.

## Estado

Aceptado

## Fecha

24 de septiembre de 2026

---

## Contexto

El Sistema de Gestión de Correspondencia permite registrar documentos y realizar derivaciones entre funcionarios y unidades.

Dentro del proceso de derivación existen diferentes comportamientos que pueden variar según el tipo de derivación.

Por ejemplo, una derivación puede ser ordinaria o urgente.

Además, cuando se realiza una derivación o cambia el estado de un documento, pueden existir diferentes componentes interesados en conocer dicho cambio.

Entre estos componentes se encuentran:

- Sistema de notificaciones.
- Sistema de auditoría.

Si toda esta lógica se concentra dentro de una única clase, el sistema puede aumentar su acoplamiento y dificultar la incorporación de nuevos comportamientos.

Durante el laboratorio H3 se analizaron diferentes patrones de diseño:

- Factory.
- Builder.
- Adapter.
- Singleton.
- Observer.
- Strategy.
- Decorator.

Después de analizar las necesidades del Sistema de Gestión de Correspondencia, se decidió realizar la integración final utilizando Strategy y Observer.

---

## Decisión

Se decidió fusionar los patrones **Strategy** y **Observer** en el módulo de gestión de derivaciones.

### Strategy

Strategy será utilizado para encapsular los diferentes comportamientos de derivación.

Las estrategias consideradas son:

- `DerivacionOrdinaria`
- `DerivacionUrgente`
